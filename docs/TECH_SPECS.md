# 📐 Pixel Wall - Technical Specifications

Technical documentation for the "Pixel Wall" Crowdfunding system implementation.

**Last Updated:** 31/01/2026 (v2.3.1 - Security Hardening & Atomic Renames)

> **⚠️ INTERNAL USE ONLY**
> This page contains sensitive details about the system structure. Do not publish or share externally.

## 1. System Architecture
The system is based on a **Serverless-like** architecture (no relational database), using flat JSON files for data persistence, managed via PHP with atomic locks to ensure consistency during concurrent writes.

- **Frontend:** HTML5 Canvas, Vanilla JS, CSS3 (No Frameworks).
- **Backend:** PHP 8.x (RESTful API), Node.js (Maintenance/reset scripts).
- **Payments:** Stripe PaymentIntent API (Server-side Verification).
-   **GDPR:** Custom "Madness GDPR System" integrated via Git Submodule (v1.2.1).
-   **Security**: Restricted CORS + CSP with dynamically generated Nonces (v1.0.12) + GCM v2 Basic Mode (v1.5.1).
- **Storage**: Secure flat-file JSON Database with atomic write protection (`flock` + `rename`).

## 2. Data Structure (JSON)
Data resides in the `pixelwall/data` subdirectory.

- `private/admin_winners_[SECRET].php`: Dashboard to view winners (Gold & Silver).
- `private/Stripe_keys_[SECRET].php`: (Deprecated v1.0.11) Replaced by `.env`.

- `pixelwall/admin_log.php`: **(v1.0.6)** Secure Admin interface for managing `updates.json` with Atomic Writes.
- `pixelwall/admin_contributions.php`: **(v1.3.1)** Financial dashboard for tracking revenue, contributor emails, and CSV export.
- `pixelwall/security_headers.php`: **(New v1.0.12)** Implements Content Security Policy (CSP) and nonces.
- `pixelwall/data/.htaccess`: **(Updated v1.3.0)** Protects sensitive JSON data while explicitly allowing public read access to the `uploads/` directory for news images.

## 3. Functional Flow

### A. Grid Rendering
1. The client downloads `data/wall_preset.json` (base) and queries `wall-api.php` (overlays user pixels).
2. HTML5 Canvas renders pixels 1:1.
3. Zoom and Pan are handled via JS coordinate transformations (without continuous DOM repainting).
4. **Optimization:** An *Offscreen Cache Canvas* is used to cache static pixels (Confirmed Wall).
5. **High-DPI Support:** Dynamic scaling via `devicePixelRatio` to ensure 1:1 pixel sharpness on Retina displays.
6. **Mobile Pinch-to-Zoom:** (New v1.2.0) Native multi-touch gesture support in "Naviga" (Pan) mode, enabling seamless magnification using two-finger pinch.

### B. Payment and Saving (Critical - v1.3.0 Update)
1. **Phase 1 (Client):** JS calculates area and pixels, calls Stripe to get a `clientSecret`.
2. **Phase 2 (Stripe):** Creates a *PaymentIntent*. Metadata includes `pixel_count` and `area_cm2`.
3. **Phase 3 (Confirmation):** User pays via Stripe Checkout. On success, Stripe redirects user back to the wall.
4. **Phase 4 (Secure Verification - "Ask & Verify"):**
    - Client sends `txnId` (Transaction ID) to `wall-api.php`.
    - **No Webhook Needed:** The server directly queries the Stripe API using the secret key to verify the transaction status is `succeeded`.
    - **Replay Protection:** Server checks `data/transactions.json`. If `txnId` exists, request is rejected.
    - **Metadata Verification:** Server calls Stripe API to verify:
        - Status is `succeeded`.
        - Number of sent pixels <= `pixel_count` in Stripe metadata.
        - Calculated area <= `area_cm2` in Stripe metadata.
    - **Atomic Commit (v2.3.1):** If all checks pass:
        1.  Acquire exclusive lock on `data/wall_data.json.lock`.
        2.  Read current data.
        3.  Write new data to `data/wall_data.json.tmp`.
        4.  **Atomic Rename:** Move `.tmp` over original `.json` (OS-level guarantees against corruption).
        5.  Release lock.

> **🔒 Security Note on Image Processing:**
> The "Image-to-Pixel" conversion is strictly **client-side**. Original image files are never uploaded to, processed by, or stored on the server. The engine reads the file locally via the `FileReader` API, processes it on an offscreen canvas, and extracts raw pixel data. This "Serverless-Upload" approach completely eliminates risks associated with malicious file uploads (RCE) and protects user privacy by never storing metadata (like GPS) from the original files.

### C. Golden Pixel System
Victory logic is **Server-side**. During pixel saving:

```php
$goldPixels = include 'private/secret_gold_pixels_xxxx.php';
$found = array_intersect($nuovi_pixel, $goldPixels);
if ($found) {
    // Register winner in winners.json (Atomic Lock)
    // Returns isWinner = true to client
}
```
The client shows the victory modal only if the server confirms.

### D. Silver Pixel System
Runs in parallel to Gold. If a pixel is not Gold, it is checked against the Silver array:
- 50 winning pixels (generated to not overlap with Gold or Preset).
- Returns `isSilverWinner` to the client.
- Activates "Silver Pixel Found" modal and updated icon in HUD.

### E. Madness News System (v1.0.6)
A lightweight "blog" system to keep users engaged.
- **Frontend:** Fetches `data/updates.json` via AJAX. Renders content with **v1.4.1 multimedia engine**:
    - **YouTube Integration:** Uses the built-in **Madness GDPR manager** for compliant loading. Iframes are wrapped in a responsive container that automatically calculates the `padding-bottom` (aspect ratio) based on the original `width`/`height` attributes to prevent layout shifts.
    - **Alignment:** Videos are left-aligned by default (matching images) but respect their maximum specified width.
    - Lightbox Gallery: Implementation of a global modal lightbox for inspecting news images at full resolution with body-scroll locking.
    - **Reaction System (New v1.4.2):** Interactive "Like" (👍) and "Heart" (❤️) buttons. Reactions are mutually exclusive (only one active per user/post) and are stored via a single atomic API call to minimize server load. User choices are persisted via `localStorage` for visual consistency across sessions.
- **Backend:** Managed via two specialized administrative interfaces:
    - `admin_log.php`: For project updates, multimedia news content (YouTube, Lightbox), and interaction management (Reactions).
    - `admin_contributions.php`: A financial dashboard for real-time tracking of crowdfunding revenue, unique supporters, and transaction logs. Includes a **CSV Export** feature for fulfillment.

### F. Winner Inspection System (v1.1.6)
Interactive tool to identify special pixel owners.
- **Client:** Clicking a star (Gold/Silver) triggers a lookup in the `winnerMap`.
- **Backend:** `wall-api.php?type=winners` performs a join between winners and contributors via `txnId` to provide Supporter Names.
- **UI:** Floating "Winner Popup" appears at click coordinates, featuring reward-specific icons (🪙/🪙).

### H. Branding Engine (v2.0.0)
Decouples visual content from code logic.
- **Persistence:** All project-specific texts are stored in `data/custom_branding.json`.
- **Injection:** `pixel-wall.js` fetches this JSON during initialization via `loadBranding()` and dynamically updates the DOM (Title, Modals, Support links).
- **Control:** The Admin Dashboard provides a dedicated "Branding" tab for non-technical users to update the project identity.

### I. Admin Session Unification (v2.0.0)
Standardized security model for the backend.
- **Single Source of Truth:** `$_SESSION['admin_logged_in']` is now the only variable used across the entire `/admin` directory.
- **Redirect Logic:** Sub-pages (`admin_log.php`, etc.) automatically redirect to the unified dashboard index if no valid session is present.

### J. High-Speed Localization (v2.0.0)
The admin interface implements a reactive language switching system.
- **Global Functionality:** All dynamic stats and settings tables are exposed via `window.loadX()` functions.
- **Instant Refresh:** `setLanguage()` triggers these functions immediately, allowing the UI to reflect language changes without a full page reload.
- **Audit-Hardening:** Every text element in both Admin and Frontend PHP files is now mapped to `data-i18n` attributes.

## 4. Maintenance and Reset
The system provides Node.js scripts for environment management and performance benchmarking.

### A. System Reset
`node pixelwall/scripts/reset_wall.js`

**What it does:**
1. Restores `data/wall_data.json`.
2. Clears transactions, owner logs, and winners (Gold and Silver).
3. Resets `data/updates.json` with a default message.
4. Uses `scripts/generate-gold-pixels.php` to calculate 10 Gold and 50 Silver coordinates (saved in `private/` with **new random suffixes** each time).
5. (Optional) Clears `access_logs.json`.

### B. Stress Testing (Development Only)
`node pixelwall/scripts/generate_noise.js`

**What it does:**
1. Populates `data/wall_data.json` with **200,000 random pixels** using the brand color palette.
2. Used for stress testing the Canvas rendering engine and verifying the **Offscreen Cache Canvas** performance with high pixel density.
